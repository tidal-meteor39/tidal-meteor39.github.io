深度解析

只在这一节提出判断，其他板块只给条目与日期。

判断一：索引表的价值在“共享 ID”，不在条目数量

2026-10-30 的分区总表把条目数从 44 改为 46，同时引入统一 ID。此前字母序表与日期序表各自编号，同一条目在两表中出现两个号，读者在交叉引用时容易对错。v4.2 起两张表共用 A-01 至 I-18 的 ID 段，编号本身成为校验手段：看到一个编号，就能判断它属于哪张表、哪个分区。

可核对的中段：v3.8 时期字母序表编号为 1—44，日期序表编号为 1—44，两套编号无对应关系；v4.2 改为分区前缀加两位序号，例如 D-07 表示常见问题分区第 7 条。变化发生在 2026-11-06 的发布记录第 3 行。

如果只看“46 条”这个数字，换一个索引工具同样能达成；真正难以复制的是 ID 与变更日志行号的对应关系——它能让人从一条记录追到一次修改。

判断二：导航层级从三级压到两级，牺牲了细分的可发现性

2026-10-20 起，导航由“主题—栏目—条目”三级改为“主题—分区”两级。好处是任何页面到目标条目不超过两次点击；代价是原先挂在第三级的 9 个栏目名被合并进分区说明，读者若只记得旧栏目名，直接输入检索词更难命中。

这组数字来自版本对照 B-02 与 B-05。判断可以说得更具体：合并带来的检索成本集中在 11-03 补充同义词之前的两周，之后 60 个旧栏目名被加入映射，命中率回升。换句话说，问题不在于压缩层级，而在于压缩与同义词补充之间有半个月的时间差。

判断三：日期序比字母序更适合核对，而字母序更适合浏览

同一批 46 条记录在两套排序下，用途不同。日期序把 11-01 至 11-08 的改动排在顶部，核对“最近改了什么”最快；字母序把同前缀条目聚在一起，浏览“某分区有哪些条目”更顺。把两张表当成互相替代，是常见误读。

可核对的依据：索引表 v4.2 的日期序在 11-06 发布时共 8 行改动，其中 5 行属新增、3 行属更正；字母序同日的改动只有 6 行可见变化，因为两条更正落在同前缀内部，视觉上不突出。数字差说明两张表的敏感度不同，而非其中一张有错。

判断四：FAQ 归档的“首次归档日”比“最后修改日”更能说明问题稳定度

96 条问答中，首次归档集中在 2026-10-10 至 10-25 的 41 条，其答复在之后三周内平均修改 1.4 次；10-26 之后归档的 55 条，平均修改 0.3 次。修改次数多的一批，问题多与导航改版同期出现，属结构性变化引发；后者属常规询问，答复更稳定。

这里需要区分事实与推测。事实是修改次数与归档日期段；推测是“结构性变化导致答复频繁变动”——这一点尚无逐条比对支撑，只有 D-12 至 D-20 九条记录显示出同类模式。若后续核对发现不成立，该推测应撤回。

体验指南：四步完成一次有效查找

步骤按实际访问顺序排列，每步给出判断何时该退回上一步。

  1. 先确认要找的是“条目”还是“栏目”

    条目有 ID，例如 D-07；栏目只有名称。若只记得名称，直接跳到第 3 步用映射表。2026-10-30 之后，栏目名不再单独占编号。

  2. 用索引表定位分区前缀

    A 至 L 共 12 个前缀，前缀本身即分区缩写。找不到前缀说明该条目尚未入表，应查变更日志的待复核区。

  3. 在检索面板叠加关键词与日期范围

    输入框支持分区名与条目 ID 两种输入。11-08 新增按更新时间排序，可与日期范围叠加，结果为空时会提示最接近的两个分区名。

  4. 回到变更日志核对改动

    命中条目后，记录其 ID 与核对日，再到变更日志找对应行号。行号与 ID 能对上，说明记录未被后续修改覆盖；对不上就回到第 2 步。

索引表 vs 变更日志：什么时候看哪一个

两者共享编号体系，但记录的信息层不同。

索引表（A—L 分区）

  • 回答“有什么”，给出条目当前状态。
  • 每条附核对日期，最多记录最近一次。
  • 字母序与日期序两张表，共用 ID。
  • 适合初次查找与浏览分区结构。

变更日志（F-01 至 F-24）

  • 回答“改过什么”，保留连续改动行。
  • 每行含时间、旧值、新值、操作人代号。
  • 行号可与索引表 ID 交叉引用。
  • 适合核对来源与追溯一次更正。

常见问题

答复主语为条目或功能，括号内为归档编号。
索引表和目录页有什么区别？（F-091）
索引表给的是条目 ID、分区前缀与核对日期，用于定位与核对；目录页只按层级列出栏目名，不含编号。两者在 v4.2 之后不再共用页面，访问路径也不同。
为什么搜旧栏目名搜不到内容？（F-092）
导航从三级压到两级后，9 个旧栏目名被并入分区说明。11-03 起 60 个旧名已加入同义词映射，输入后会自动转向新分区，但显示的是分区名而非原栏目名。
条目 ID 里的字母代表什么？（F-093）
字母是分区前缀，A 为分区总表，B 为版本对照，D 为常见问题，依次至 L。字母后的两位数字只在所属分区内递增，跨分区不连续。
变更日志里的“旧值/新值”如何核对？（F-094）
先在索引表记下条目 ID，再到日志找同行号。若日志显示的新值与索引表当前值一致，说明该条未被后续修改覆盖；不一致时以日志中较晚的时间为准，并在反馈表单提交条目编号。
检索结果为空怎么办？（F-095）
面板会提示最接近的两个分区名，可先点入分区再浏览字母序表。若仍无结果，说明条目尚未入表，应查变更日志的待复核区，那里保留 9 条未定项。
反馈建议多久会被处理？（F-096）
10 月共 23 条建议，14 条在提交后 7 日内并入索引，其余 9 条转待复核。11-01 起表单新增条目编号字段，含编号的建议处理更快，平均 4 日。
